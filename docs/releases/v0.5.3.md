FlowLabs: data, SQL and machine learning in one place. Free and open source (MIT).

## New: Databases

A new **Databases** page, next to Projects and Guide, for working in PostgreSQL, MySQL and MariaDB
(and SQLite files) without pgAdmin or MySQL Workbench.

- **Browse** every database and schema: tables, views, functions, procedures, triggers and
  sequences. Each table shows its rows, columns, keys, indexes and CREATE script.
- **Query tabs** keep their own connection, so transactions, `SET`, `USE` and temporary tables last
  from one run to the next.
  - <kbd>Ctrl</kbd>+<kbd>Enter</kbd> runs the statement under the cursor;
    <kbd>Shift</kbd>+<kbd>Ctrl</kbd>+<kbd>Enter</kbd> runs them all.
  - **Stop** cancels a running query on the server.
  - **Auto-commit** can be turned off, with **Commit** and **Roll back**.
  - Results show the first 500 rows without fetching the rest, so huge tables stay fast.
  - History, errors marked on their line, and completion of table and column names.
- **Explain** and **Explain and run** show the query plan as a tree, with times, row counts, and a
  hint where a whole table is read.
- **Export** a result to CSV, Excel, JSON or Parquet, or keep it as a dataset to train models on.
- **Edit rows** in place, add and delete them. The exact SQL is shown before saving, and it all runs
  in one transaction. If someone else changed a row meanwhile, nothing is saved.
- **Import a dataset** into a new or existing table.
- **Server activity:** connections, uptime, size and every running query, with **Stop query** and
  **End session**.
- **Users and roles:** see what each may do; create users, change passwords, grant and revoke, with
  the SQL shown first (passwords hidden).

## Connections

- One **Connect** dialog for every kind of source, here and in a project's SQL view: databases,
  warehouses (Snowflake, BigQuery, Redshift, Databricks) and cloud storage. A missing driver
  installs from the dialog.
- **SSL** for MySQL and MariaDB, and certificate checking for PostgreSQL and MySQL.
- **SSH tunnels** for databases behind a firewall, signing in with a key, a password or your SSH
  agent. The SSH server's key is checked: you trust it once, and a changed key is refused.
- **Read-only** connections are now read-only on the server itself, so a function that writes
  cannot slip through.
- Passwords and keys are kept in the system keychain (macOS Keychain, Windows Credential Manager,
  the Secret Service on Linux).
